## 6. Known Defects

**Schema Drift Detection Failure:**
- **Injected Condition**: An unexpected column (`UNEXPECTED_TEST_COLUMN`) was added to `processed_claims` via `ALTER TABLE` in duckdb.
- **Observed Result**: The engine produced no schema drift findings.
- **Root Cause**: The current implementation extracts schema metadata dynamically from a Pandas DataFrame generated by `con.execute("SELECT * FROM processed_claims WHERE run_id = ?").df()`. Because DuckDB maintains a static tabular schema, altering the table to include a new column inherently projects that column across *all* rows, regardless of `run_id`. Consequently, `current_schema` and `historical_schema` are always structurally identical.
- **Recommended Correction**: None immediately necessary for Phase G closure, but future iterations should evaluate schemas against an external JSON contract or a dedicated manifest, rather than trusting `SELECT *`.
