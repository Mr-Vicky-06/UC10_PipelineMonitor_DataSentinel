# PHASE 7 — SLA UI CONTRACT

## Authoritative SLA Source
The SLA engine correctly calculates and determines `AT_RISK` or `BREACHED` states based on the `SLACalculator` executing against real pipeline telemetry. 

The resulting SLA evidence is persisted in the **Alert Engine** `alertdb.sqlite3` database within the `alert_details` table, specifically inside the `details_json` column.

## Frontend UI Contract Map

The frontend will **NEVER** calculate SLA ETA or throughput internally. It will strictly read and format the evidence from the Alert Engine.

| Frontend UI Field      | Alert Engine Backend Source                           | Calculation Owner | Refresh Mechanism       |
|-----------------------|-------------------------------------------------------|-------------------|--------------------------|
| `sla_status`          | `alerts.severity` (HIGH/CRITICAL on `event_type=SLA`) | SLACalculator     | Alert Engine WebSocket / Polling |
| `eta`                 | `alert_details.details_json.estimated_completion`     | SLACalculator     | Alert Engine WebSocket / Polling |
| `deadline`            | `alert_details.details_json.deadline`                 | SLAConfigManager  | Static (Config)          |
| `pipeline_status`     | `alert_details.details_json.pipeline_status`          | Pipeline Engine   | Pipeline Telemetry       |
| `throughput`          | *NOT EMITTED in details_json*                         | *N/A*             | *UNAVAILABLE*            |
| `required_throughput` | *NOT EMITTED in details_json*                         | *N/A*             | *UNAVAILABLE*            |

### Missing Fields
- `throughput` and `required_throughput` do not currently exist in the `details_json` payload generated by the backend's ActionEngine for SLA alerts. The UI will explicitly display `UNAVAILABLE` rather than attempting to calculate these values locally.

### Required API Adapter Fix
To fulfill this contract, the `api/alerts` Next.js endpoint must be extended to query or receive the `alert_details` joined onto the `alerts` table from the FastAPI Alert Engine. Currently, `/api/v1/alerts` only returns the base summary. If `/api/v1/alerts/{alert_id}` returns details, the frontend adapter should fetch them, or the FastAPI backend should be adjusted to include `details_json` in the primary list endpoint.

> [!WARNING]
> Since the FastAPI backend is frozen, if `/api/v1/alerts` does not provide `details_json`, the frontend `api/alerts` adapter will have to loop through and fetch `/api/v1/alerts/{alert_id}` for SLA events, or directly query the `alertdb.sqlite3` database to extract the `details_json` if direct DB access is permitted for this adapter.
