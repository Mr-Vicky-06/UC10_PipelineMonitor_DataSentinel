# PHASE 5C FINAL RCA ACCEPTANCE REPORT

## 1. RCA Architecture
The RCA module acts as the authoritative intelligence layer, receiving canonical `EvidencePack` objects generated by the RAG retrieval layer and outputting structured JSON insights. It enforces a strict separation of concerns:
- **LLM (Gemini)**: Responsible only for human-readable synthesis and establishing correlations supported directly by evidence.
- **Deterministic Engine**: Wraps the LLM generation, enforcing strict severity mapping, evidence-grounded confidence scores, and hallucination rejection (via `CitationValidator`).

## 2. RCAResponse Contract
The `RCAResponse` schema was finalized to be strict, trace-proven, and backwards compatible. 
```json
{
    "incident_id": "INC-...",
    "run_id": "string",
    "hospital_id": "string",
    "batch_id": "string",
    "affected_stage": "string",
    "anomaly_types": ["string"],
    "severity": "CRITICAL|ERROR|WARNING|INFO",
    "status": "OPEN",
    "summary": "string",
    "what_happened": "string",
    "evidence": [{"evidence_id": "string", "description": "string"}],
    "facts": [{"description": "string", "evidence_ids": ["string"]}],
    "confirmed_findings": [{"description": "string", "evidence_ids": ["string"]}],
    "correlated_findings": [{"description": "string", "evidence_ids": ["string"]}],
    "likely_causes": [{"cause": "string", "supporting_evidence_ids": ["string"]}],
    "confidence": "HIGH|MEDIUM|LOW|ZERO",
    "recommended_investigation": "string",
    "sla_status": "ON_TRACK|AT_RISK|BREACHED|UNKNOWN",
    "source_references": ["string"],
    "created_at": "timestamp"
}
```

## 3. Backward Compatibility
The contract ensures no breakages for existing alert consumers by preserving `affected_hospital` and `affected_batch` as `@property` getters mapped to `hospital_id` and `batch_id`.

## 4. Evidence Correlation
The system extracts dynamic data combining structural pipeline logging (`pipeline_events`), business rules (`rule_results`), anomaly signatures (`anomaly_events`), and SLA evaluations (`sla_status`). The deterministic layer ensures all multi-signal correlation retains explicit `evidence_ids`.

## 5. Fact/Correlation/Cause Separation
Enforced within the LLM instructions and Pydantic schema:
- **Facts**: Direct observations from telemetry.
- **Confirmed Findings**: Guaranteed proof.
- **Correlated Findings**: Temporally/Spatially linked events.
- **Likely Causes**: Rejected by instructions unless definitively supported.

## 6. Severity Algorithm
Calculated deterministically outside the LLM:
1. Extract severities from all incoming `Evidence`.
2. Enforce strict precedence: `CRITICAL` > `ERROR` > `WARNING` > `INFO`.
3. Overwrite LLM response entirely to ensure 0% hallucinated severities.

## 7. Confidence Algorithm
Calculated deterministically outside the LLM:
- **HIGH**: Direct failure evidence present (`rule_violation` or `pipeline_failure`).
- **MEDIUM**: Multi-signal inference present (e.g., `statistical_anomaly` + `sla_status`).
- **LOW**: Singular indirect indicator (e.g., only `statistical_anomaly`).
- **ZERO**: `Insufficient evidence`.

## 8. SLA Integration
SLA information is correctly incorporated dynamically during retrieval via the `SLAConfigManager` and `SLACalculator`, passing structured `sla_status` evidence explicitly into the `EvidencePack`.

## 9. Gemini Grounding
The LLM is rigorously bound to the explicit telemetry inside `evidence_pack_json`. It is explicitly commanded not to invent anomalies, and must abstain if evidence is lacking.

## 10. Citation Validation
`CitationValidator` was hardened from "soft-repair" to "strict rejection". Any fabricated `evidence_id` in `facts`, `findings`, `causes`, or `source_references` triggers an immediate `ValueError`, dropping the hallucination completely.

## 11. Offline Fallback
In scenarios where the API Key is missing, network is unavailable, or a severe LLM hallucination is rejected, the system falls back to a deterministic mode, creating an `INC-FALLBACK` incident preserving all factual evidence while yielding "Insufficient evidence to determine root cause due to LLM failure".
